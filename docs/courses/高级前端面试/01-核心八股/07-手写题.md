# JavaScript 手写题

手写题先说明边界，再写主流程，最后补异常和测试。闷头写代码，会丢掉很多展示思路的机会。

## Q1：实现防抖

### 这题在考什么

是否理解防抖的核心机制：每次调用都取消上一次计时，只保留最后一次。同时，实现里还要保留调用时的 `this` 和参数、提供取消能力，而不是只会背一段 `setTimeout` 代码。

### 面试时可以这样说

> 防抖的核心很简单：每次调用都取消上一次计时，只保留最后一次。实现的时候注意三点：保留调用时的 `this` 和参数；提供取消能力；要不要支持立即执行，先和面试官确认一下。

### 如果对方让你继续讲

完整实现如下：

```js
function debounce(fn, wait) {
  let timer = null

  function debounced(...args) {
    const context = this
    clearTimeout(timer)
    timer = setTimeout(() => {
      timer = null
      fn.apply(context, args)
    }, wait)
  }

  debounced.cancel = () => {
    clearTimeout(timer)
    timer = null
  }

  return debounced
}
```

### 对方很可能继续问

**如何支持 leading/trailing？**

**返回值如何处理？**

**组件卸载时为什么要 cancel？**

### 一句话记住

每次调用都取消上一次计时，只保留最后一次。

## Q2：实现并发限制器

### 这题在考什么

是否理解并发限制器靠活跃计数加等待队列，维持 `activeCount <= limit` 这个不变量。同时，无论任务成功、失败还是同步抛错，都要释放名额，而不是只会背队列代码。

### 面试时可以这样说

> 核心是维护两个东西：正在运行的数量，和等待队列。任务结束以后，无论成功还是失败，都要释放名额，再启动下一个任务。也就是说，名额的释放放在 `finally` 里，任务同步抛错也不会漏掉。

### 如果对方让你继续讲

完整实现如下：

```js
function createLimiter(limit) {
  let activeCount = 0
  const queue = []

  function runNext() {
    if (activeCount >= limit || queue.length === 0) return

    const { task, resolve, reject } = queue.shift()
    activeCount += 1

    Promise.resolve()
      .then(task)
      .then(resolve, reject)
      .finally(() => {
        activeCount -= 1
        runNext()
      })
  }

  return function limitTask(task) {
    return new Promise((resolve, reject) => {
      queue.push({ task, resolve, reject })
      runNext()
    })
  }
}
```

### 对方很可能继续问

**如何取消排队任务？**

**如何保证公平性？**

**如何增加优先级、超时和重试？**

### 一句话记住

计数封顶，队列排队，名额在 `finally` 释放。

## Q3：实现深拷贝前要问什么？

### 这题在考什么

是否把深拷贝当成接口定义来做——先确认支持范围，再谈实现，而不是宣称一个没有范围的“完整深拷贝”。

### 面试时可以这样说

> 我会先确认支持范围。业务代码优先考虑 `structuredClone`，它支持循环引用和多种内建类型，但不能克隆函数和部分宿主对象。如果要求手写，需要明确是否处理 Symbol key、属性描述符、原型、Map、Set、Date、RegExp、循环引用和不可枚举属性。没有范围的“完整深拷贝”是不严谨的题目。

### 如果对方让你继续讲

核心版本如下：

```js
function deepClone(value, seen = new WeakMap()) {
  if (value === null || typeof value !== 'object') return value
  if (seen.has(value)) return seen.get(value)
  if (value instanceof Date) return new Date(value.getTime())
  if (value instanceof RegExp) return new RegExp(value.source, value.flags)

  if (value instanceof Map) {
    const result = new Map()
    seen.set(value, result)
    for (const [key, item] of value) {
      result.set(deepClone(key, seen), deepClone(item, seen))
    }
    return result
  }

  if (value instanceof Set) {
    const result = new Set()
    seen.set(value, result)
    for (const item of value) result.add(deepClone(item, seen))
    return result
  }

  const result = Array.isArray(value)
    ? []
    : Object.create(Object.getPrototypeOf(value))

  seen.set(value, result)
  for (const key of Reflect.ownKeys(value)) {
    result[key] = deepClone(value[key], seen)
  }
  return result
}
```

### 一句话记住

先问支持范围，再写实现；业务代码优先 `structuredClone`。

## Q4：实现 Promise.all

### 这题在考什么

是否理解 `Promise.all` 的语义约束：结果按下标写入，保持输入顺序；任意一个拒绝，外层 Promise 就拒绝；空输入立即兑现；而不是只会默写收集结果的循环。

### 面试时可以这样说

> 先说清楚五个要点。第一，结果按下标写入，保持输入顺序，而不是完成顺序。第二，普通值统一用 `Promise.resolve` 包一层。第三，任意一个拒绝，外层 Promise 就拒绝。第四，空输入立即兑现空数组。注意一点：已经启动的其他任务不会被自动取消。

### 如果对方让你继续讲

完整实现如下：

```js
function promiseAll(iterable) {
  return new Promise((resolve, reject) => {
    const values = Array.from(iterable)
    const result = new Array(values.length)
    let completed = 0

    if (values.length === 0) {
      resolve([])
      return
    }

    values.forEach((value, index) => {
      Promise.resolve(value).then((item) => {
        result[index] = item
        completed += 1
        if (completed === values.length) resolve(result)
      }, reject)
    })
  })
}
```

### 一句话记住

结果按下标写入：保持输入顺序，一拒全拒。

## Q5：实现 new

### 这题在考什么

是否理解 `new` 的完整过程——建新对象、挂原型、以新对象为 `this` 执行构造函数、按规则处理返回值，而不是只会背四行代码。

### 面试时可以这样说

> `new` 一共四步。第一步，用 `Object.create` 创建新对象，把原型指到构造函数的 `prototype`。第二步，以新对象作为 `this` 执行构造函数。第三步，看返回值：构造函数返回的是对象或者函数，就返回它；否则返回新实例。

### 如果对方让你继续讲

完整实现如下：

```js
function myNew(Constructor, ...args) {
  const instance = Object.create(Constructor.prototype)
  const returned = Constructor.apply(instance, args)
  const isObject = returned !== null
    && (typeof returned === 'object' || typeof returned === 'function')

  return isObject ? returned : instance
}
```

### 对方很可能继续问

**构造函数返回原始值会怎样？**

**返回对象会怎样？**

**为什么 class 构造函数不能直接用 `apply` 调用？**

### 一句话记住

构造函数返回对象才覆盖实例，否则返回新对象。

## Q6：如何设计重试函数？

### 这题在考什么

是否把重试当成完整设计来做：先界定可重试的错误、次数与总超时、退避策略、幂等性、取消和错误链，而不是只写一个递归函数。

### 面试时可以这样说

> 不要只写递归。我会先说明六件事：哪些错误允许重试；最大次数和总超时；指数退避与随机抖动；幂等性；`AbortSignal` 取消；最终错误保留原始原因。注意一点：支付、创建订单这类非幂等操作，不能因为网络超时就盲目重试。

### 一句话记住

先说清重试边界，再动手写；非幂等操作不盲目重试。

## 面试现场怎么写得更像高级工程师

### 先确认范围

例如手写深拷贝时可以先问：“需要支持 Map、Set、循环引用和属性描述符吗？函数是保持引用还是报错？”先把这些问清楚，不是拖延，而是在定义接口。没有范围就宣称“完整深拷贝”，反而容易被追问击穿。

### 边写边说不变量

并发限制器最重要的不变量是 `activeCount <= limit`，无论任务成功、失败还是同步抛错，都要释放名额。`Promise.all` 最重要的是结果保持输入顺序，而不是完成顺序。先说清这些再落代码，面试官更容易看出你的设计能力。

### 主动补测试

写完至少口述三个测试：空输入、失败路径、边界参数。以防抖为例，还应覆盖组件卸载前取消、连续快速调用以及回调里的 `this`。只跑一个 happy path，代码看起来能用，但不够可靠。

### 被追问“生产环境会这样写吗”

可以坦诚回答：“面试实现展示的是核心机制。生产环境我会优先用经过测试的库或平台原生能力，同时补类型、取消、监控和兼容处理。”这样答，比硬说几十行代码已经生产可用更可信。

## 自测

1. 为防抖补 leading/trailing 测试。
2. 让并发限制器处理同步抛错任务。
3. 解释深拷贝为什么必须先限定支持范围。
4. 解释 `Promise.all` 为什么不能取消已经发出的请求。
