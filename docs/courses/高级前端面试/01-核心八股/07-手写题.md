# JavaScript 手写题

手写题先说明边界，再写主流程，最后补异常和测试。闷头写代码，会丢掉很多展示思路的机会。

## Q1：实现防抖

### 这题在考什么

考你能不能抓住防抖的核心机制——**每次调用都取消上一次计时，只保留最后一次**；实现里还要保留调用时的 `this` 和参数、提供取消能力，而不是只会背一段 `setTimeout` 代码。

### 面试时可以这样说

> 防抖的核心很简单：每次调用都取消上一次计时，只保留最后一次。实现的时候注意三点：保留调用时的 `this` 和参数；提供取消能力；要不要支持立即执行，先和面试官确认一下。

**核心一句话**：“每次调用都取消上一次计时，只保留最后一次。”

### 如果对方让你继续讲

完整实现如下：

```js
function debounce(fn, wait) {
  let timer = null

  function debounced(...args) {
    const context = this
    clearTimeout(timer)
    timer = setTimeout(() => {
      timer = null
      fn.apply(context, args)
    }, wait)
  }

  debounced.cancel = () => {
    clearTimeout(timer)
    timer = null
  }

  return debounced
}
```

### 对方很可能继续问

**如何支持 leading/trailing？**

leading 是第一次调用立即执行、后续调用只重置计时；trailing 是停止触发后再等 `wait` 执行。实现上多记一个“上次触发时间”，判断该立即执行还是继续等，lodash 的 debounce 两个开关可以组合。

**返回值如何处理？**

防抖函数拿不到原函数的返回值，因为调用被推迟了。需要结果时，改成把回调传进去，或让包装函数返回 Promise，取消时统一 reject。

**组件卸载时为什么要 cancel？**

组件卸载后，未触发的回调仍会执行，可能操作已卸载的 DOM 或更新失效的状态。`cancel` 清掉计时器，把这个尾巴掐掉。

### 一句话记住

每次调用都取消上一次计时，只保留最后一次。

## Q2：实现并发限制器

### 这题在考什么

考你能不能抓住并发限制器的两个要素——**活跃计数加等待队列**，维持 `activeCount <= limit` 这个不变量；无论任务成功、失败还是同步抛错都要释放名额，而不是只会背队列代码。

### 面试时可以这样说

> 核心是维护两个东西：正在运行的数量，和等待队列。任务结束以后，无论成功还是失败，都要释放名额，再启动下一个任务。也就是说，名额的释放放在 `finally` 里，任务同步抛错也不会漏掉。

**核心一句话**：“计数封顶，队列排队，名额在 `finally` 释放。”

### 如果对方让你继续讲

完整实现如下：

```js
function createLimiter(limit) {
  let activeCount = 0
  const queue = []

  function runNext() {
    if (activeCount >= limit || queue.length === 0) return

    const { task, resolve, reject } = queue.shift()
    activeCount += 1

    Promise.resolve()
      .then(task)
      .then(resolve, reject)
      .finally(() => {
        activeCount -= 1
        runNext()
      })
  }

  return function limitTask(task) {
    return new Promise((resolve, reject) => {
      queue.push({ task, resolve, reject })
      runNext()
    })
  }
}
```

### 对方很可能继续问

**如何取消排队任务？**

排队时给每个任务带上取消标记或 `AbortSignal`，出队执行前先检查；已经开始的任务，只能靠任务内部响应 signal 自行中止。

**如何保证公平性？**

现在的等待队列就是先进先出，天然按提交顺序公平；要区分优先级，把普通队列换成堆，出队时取优先级最高的即可。

**如何增加优先级、超时和重试？**

超时给 task 套一层带拒绝的定时 Promise，重试包一层带退避的重试器，优先级把普通队列换成堆。三者都能叠加在这个骨架上，核心不变量 `activeCount <= limit` 不用动。

### 一句话记住

计数封顶，队列排队，名额在 `finally` 释放。

## Q3：实现深拷贝前要问什么？

### 这题在考什么

考你能不能把深拷贝当**接口定义**来做——先确认支持范围，再谈实现，而不是宣称一个没有范围的“完整深拷贝”。

### 面试时可以这样说

> 我会先确认支持范围。业务代码优先考虑 `structuredClone`，它支持循环引用和多种内建类型，但不能克隆函数和部分宿主对象。如果要求手写，需要明确是否处理 Symbol key、属性描述符、原型、Map、Set、Date、RegExp、循环引用和不可枚举属性。没有范围的“完整深拷贝”是不严谨的题目。

**核心一句话**：“先问支持范围，业务代码优先 `structuredClone`。”

### 如果对方让你继续讲

核心版本如下：

```js
function deepClone(value, seen = new WeakMap()) {
  if (value === null || typeof value !== 'object') return value
  if (seen.has(value)) return seen.get(value)
  if (value instanceof Date) return new Date(value.getTime())
  if (value instanceof RegExp) return new RegExp(value.source, value.flags)

  if (value instanceof Map) {
    const result = new Map()
    seen.set(value, result)
    for (const [key, item] of value) {
      result.set(deepClone(key, seen), deepClone(item, seen))
    }
    return result
  }

  if (value instanceof Set) {
    const result = new Set()
    seen.set(value, result)
    for (const item of value) result.add(deepClone(item, seen))
    return result
  }

  const result = Array.isArray(value)
    ? []
    : Object.create(Object.getPrototypeOf(value))

  seen.set(value, result)
  for (const key of Reflect.ownKeys(value)) {
    result[key] = deepClone(value[key], seen)
  }
  return result
}
```

### 一句话记住

先问支持范围，再写实现；业务代码优先 `structuredClone`。

## Q4：实现 Promise.all

### 这题在考什么

考你能不能抓住 `Promise.all` 的语义约束——**结果按下标写入、保持输入顺序；一拒即拒；空输入立即兑现**，而不是只会默写收集结果的循环。

### 面试时可以这样说

> 先说清楚五个要点。第一，结果按下标写入，保持输入顺序，而不是完成顺序。第二，普通值统一用 `Promise.resolve` 包一层。第三，任意一个拒绝，外层 Promise 就拒绝。第四，空输入立即兑现空数组。注意一点：已经启动的其他任务不会被自动取消。

**核心一句话**：“结果按下标写入保持输入顺序，一拒全拒。”

### 如果对方让你继续讲

完整实现如下：

```js
function promiseAll(iterable) {
  return new Promise((resolve, reject) => {
    const values = Array.from(iterable)
    const result = new Array(values.length)
    let completed = 0

    if (values.length === 0) {
      resolve([])
      return
    }

    values.forEach((value, index) => {
      Promise.resolve(value).then((item) => {
        result[index] = item
        completed += 1
        if (completed === values.length) resolve(result)
      }, reject)
    })
  })
}
```

### 一句话记住

结果按下标写入：保持输入顺序，一拒全拒。

## Q5：实现 new

### 这题在考什么

考你能不能完整说出 `new` 的过程——**建新对象、挂原型、以新对象为 `this` 执行、按规则处理返回值**，而不是只会背四行代码。

### 面试时可以这样说

> `new` 一共四步。第一步，用 `Object.create` 创建新对象，把原型指到构造函数的 `prototype`。第二步，以新对象作为 `this` 执行构造函数。第三步，看返回值：构造函数返回的是对象或者函数，就返回它；否则返回新实例。

**核心一句话**：“返回对象才覆盖实例，否则返回新对象。”

### 如果对方让你继续讲

完整实现如下：

```js
function myNew(Constructor, ...args) {
  const instance = Object.create(Constructor.prototype)
  const returned = Constructor.apply(instance, args)
  const isObject = returned !== null
    && (typeof returned === 'object' || typeof returned === 'function')

  return isObject ? returned : instance
}
```

### 对方很可能继续问

**构造函数返回原始值会怎样？**

被忽略，`new` 表达式仍然返回新实例；只有返回对象或函数才会覆盖。

**返回对象会怎样？**

它取代新实例成为 `new` 的结果。这也是实现“返回内部池化对象、单例”这类模式的口子。

**为什么 class 构造函数不能直接用 `apply` 调用？**

class 构造函数禁止不带 `new` 的调用，内部调用会直接抛 `TypeError`。要兼容 class，得改用 `Reflect.construct(Constructor, args)`。

### 一句话记住

构造函数返回对象才覆盖实例，否则返回新对象。

## Q7：实现节流

### 这题在考什么

考你能不能分清节流和防抖的边界——**防抖是“等不动了才执行”，节流是“固定时间窗口内最多执行一次”**；实现里要保留 `this` 和参数，还要答得上“第一次立即执行、最后一次不丢”这两个细节。

### 面试时可以这样说

> 节流是固定时间窗口内最多执行一次。和防抖的区别是：防抖是“等不动了才执行”，节流是“按频率执行”。我用时间戳加定时器结合的版本：时间戳保证第一次立即执行，定时器保证停止触发之后，最后一次调用还会被补执行。老规矩，`this` 和参数保留，另外提供取消方法。

**核心一句话**：“固定频率放行，第一次立即、最后一次不丢。”

### 如果对方让你继续讲

完整实现如下：

```js
function throttle(fn, interval) {
  let lastTime = 0
  let timer = null

  function throttled(...args) {
    const context = this
    const remaining = interval - (Date.now() - lastTime)

    if (remaining <= 0) {
      // 到达窗口边界，立即执行并记下本次时间
      if (timer) {
        clearTimeout(timer)
        timer = null
      }
      lastTime = Date.now()
      fn.apply(context, args)
    } else if (!timer) {
      // 窗口未到，挂一个定时器保证最后一次触发被补执行
      timer = setTimeout(() => {
        timer = null
        lastTime = Date.now()
        fn.apply(context, args)
      }, remaining)
    }
  }

  throttled.cancel = () => {
    clearTimeout(timer)
    timer = null
    lastTime = 0
  }

  return throttled
}
```

### 对方很可能继续问

**节流和防抖分别适合什么场景？**

搜索框输入用防抖：用户停止输入才发请求，中间的按键没有意义，只保留最后一次。滚动、resize、鼠标移动用节流：这些事件需要持续响应，防抖要等事件完全停止才执行，滚动加载会“卡住不动”；节流保证按固定频率处理，比如每 200ms 算一次滚动位置。

**trailing 最后一次触发会不会丢？**

纯时间戳版本会丢：最后一次触发落在窗口内，窗口结束后事件不再来，这次调用就被忽略了。所以要在窗口内补一个定时器，把剩余时间的最后一次调用补执行，这就是时间戳加定时器结合版的意义。只要求 trailing 不要求 leading 的话，单用定时器也能实现。

**如何支持取消？**

和防抖一样，在返回的函数上挂 `cancel`：清掉定时器、重置上次执行时间。典型场景是组件卸载时调用，避免定时器还往已卸载组件的状态里写数据。

### 一句话记住

固定频率放行，第一次立即、最后一次不丢。

## Q8：实现 Event Emitter（发布订阅）

### 这题在考什么

考你能不能把发布订阅落成**事件名到回调数组的映射**——`on` 是追加、`off` 按**同一函数引用**移除、`once` 执行后自动解绑、`emit` 先拷贝数组再遍历，而不是只会写 `on` 和 `emit`。

### 面试时可以这样说

> 发布订阅的核心是一个 Map：事件名对应一组监听器。`on` 往数组追加；`off` 按函数引用移除，所以匿名函数解绑不掉，必须保存引用；`once` 包一层，执行前先把自己解绑；`emit` 拷贝一份监听器数组再依次调用，避免执行过程中增删监听器导致遍历错乱。

**核心一句话**：“事件名映射回调数组，off 认同一函数引用，emit 先拷贝再遍历。”

### 如果对方让你继续讲

完整实现如下：

```js
class EventEmitter {
  constructor() {
    this.events = new Map()
  }

  on(event, listener) {
    if (!this.events.has(event)) this.events.set(event, [])
    this.events.get(event).push(listener)
    return this
  }

  off(event, listener) {
    const listeners = this.events.get(event)
    if (!listeners) return this
    const index = listeners.findIndex(
      (item) => item === listener || item._origin === listener
    )
    if (index > -1) listeners.splice(index, 1)
    return this
  }

  once(event, listener) {
    const wrapper = (...args) => {
      this.off(event, wrapper)
      listener(...args)
    }
    // 挂上原函数引用，off 原始引用也能解绑
    wrapper._origin = listener
    this.on(event, wrapper)
    return this
  }

  emit(event, ...args) {
    const listeners = this.events.get(event)
    if (!listeners || listeners.length === 0) return false
    // 拷贝一份再遍历，防止执行中增删监听器导致错乱
    for (const listener of [...listeners]) listener(...args)
    return true
  }
}
```

### 对方很可能继续问

**once 是怎么实现的？**

不直接存原函数，而是存一个包装函数：第一次被调用时先把自己从监听列表里 `off` 掉，再执行原函数。注意 `off` 要能同时认包装引用和原函数引用——用户手里只有原函数，解绑时传的是它，实现里靠 `_origin` 回溯到包装函数。

**emit 时某个监听器抛错怎么办？**

现在的写法会中断后面的监听器。Node 的 EventEmitter 做法是让异常直接往上抛，交给最外层 `try/catch` 或 `uncaughtException` 兜底；如果要求监听器互不影响，就在循环里逐个 `try/catch`，把错误收集或上报。面试时先确认预期行为再选方案。

**跨模块滥用事件总线会导致什么问题？**

事件流向不可追踪：发布方和订阅方之间没有静态依赖，跳转定义看不到调用关系，排查“谁发的、谁消费的”全靠全局搜索。时序问题还藏在运行时——组件卸载忘了 `off` 就会泄漏或收到重复回调。大型项目里事件总线只适合真正的跨层广播，模块间通信优先显式的依赖注入或状态管理。

### 一句话记住

事件名映射回调数组，off 认同一函数引用，emit 先拷贝再遍历。

## Q9：实现 LRU 缓存

### 这题在考什么

考你能不能利用 **Map 的插入序**把 LRU 做到 O(1)——`get` 时删掉再重插把 key 移到最新位置，超容量删 `keys().next().value` 这个最旧的 key，而不是用数组模拟退化成 O(n)。

### 面试时可以这样说

> LRU 是最近最少使用淘汰。关键点：JavaScript 的 Map 保插入序，迭代出来的第一个就是最旧的。所以 `get` 命中后，把这个 key 删掉再 `set` 回去，它就变成最新；`put` 已存在的 key 同样先删再插。容量超限时，用 `keys().next().value` 拿到最旧的 key 删掉。所有操作都是 O(1)。

**核心一句话**：“Map 保插入序，get 删了重插，超容删第一个。”

### 如果对方让你继续讲

完整实现如下：

```js
class LRUCache {
  constructor(capacity) {
    this.capacity = capacity
    this.cache = new Map()
  }

  get(key) {
    if (!this.cache.has(key)) return -1

    const value = this.cache.get(key)
    // 删掉再重插，把该 key 移到“最新”位置
    this.cache.delete(key)
    this.cache.set(key, value)
    return value
  }

  put(key, value) {
    // 已存在的 key 同样先删再插，保证它变成最新
    if (this.cache.has(key)) this.cache.delete(key)
    this.cache.set(key, value)

    if (this.cache.size > this.capacity) {
      // 迭代的第一个 key 就是插入最早的，即最久未使用
      const oldest = this.cache.keys().next().value
      this.cache.delete(oldest)
    }
  }
}
```

### 对方很可能继续问

**为什么 Map 能做到 O(1)？**

JS 规范规定 Map 按插入序记录键值对：查找、插入、删除按 key 都是哈希级别的 O(1)，迭代时又按插入序输出，两个能力正好是 LRU 需要的。普通对象不行，它的键序有“整数键排前面”这类特殊规则，删除属性也不保证高效。

**put 已存在的 key 要不要更新位置？**

要。LRU 淘汰的是“最久未被访问”，写入也是一次访问。如果 `put` 只改值不挪位置，这个 key 会被当成最旧的先淘汰，语义就错了。所以已存在的 key 同样要先删再插，对应代码里那一行 `delete`。

**和 FIFO 的区别？**

FIFO 只看进入顺序，谁先进来谁先淘汰，访问不影响位置。LRU 每次访问（`get` 或 `put`）都把该 key 移到最新位置，淘汰的是最久没被访问的。对应到实现就是“删了重插”这一步，去掉它就退化成 FIFO。

### 一句话记住

Map 保插入序：get 删了重插，超容删第一个 key。

## Q10：实现 call 和 bind

### 这题在考什么

考你懂不懂显式绑定的底层机制——**`call` 是把函数临时挂到 context 上调用再删掉，`bind` 是返回闭包预设 this 和参数且 `new` 调用时构造优先**；细节还包括 context 为空挂 `globalThis`、用 `Symbol` 避免覆盖已有属性。

### 面试时可以这样说

> `call` 的思路：把函数作为属性临时挂到 context 上，调用完再删掉。context 为 `null`、`undefined` 或原始值时挂到 `globalThis` 上，属性名用 `Symbol`，避免覆盖对象已有的属性。`bind` 的思路：返回一个闭包，内部 `apply` 预设的 this，外层参数和内层参数拼接实现柯里化。注意 `new` 调用它时，this 以构造调用为准，预设的 this 失效。

**核心一句话**：“call 临时挂载调用，bind 闭包预设且构造优先。”

### 如果对方让你继续讲

完整实现如下：

```js
Function.prototype.myCall = function (context, ...args) {
  // null/undefined 或原始值，统一包装后挂到对象或全局上
  context = context !== null && context !== undefined
    ? Object(context)
    : globalThis
  const key = Symbol('fn')
  context[key] = this
  const result = context[key](...args)
  delete context[key]
  return result
}

Function.prototype.myBind = function (context, ...outerArgs) {
  const fn = this

  function bound(...innerArgs) {
    // new 调用时 this 是 bound 的实例，以构造调用为准
    if (this instanceof bound) {
      return new fn(...outerArgs, ...innerArgs)
    }
    return fn.apply(context, [...outerArgs, ...innerArgs])
  }

  // 维护原型关系，new 出来的实例能访问原函数 prototype 上的属性
  bound.prototype = Object.create(fn.prototype)
  return bound
}
```

### 对方很可能继续问

**bind 返回的函数被 new 时，预设 this 为什么失效？**

`new` 的绑定优先级高于显式绑定：构造调用会创建全新对象作为 `this`，`bind` 预设的 context 被完全忽略。所以实现里要判断 `this instanceof bound`，构造调用就走 `new fn(...)` 让新实例当 `this`；同时把 `bound.prototype` 指到原函数的原型上，实例才能拿到原型方法。

**箭头函数为什么不能被 call/bind 改 this？**

箭头函数没有自己的 `this`，它用的是定义位置外层作用域的 `this`，声明时就确定了。`call`、`apply`、`bind` 传的第一个参数会被直接忽略，改不了指向；不过 `bind` 的柯里化传参仍然有效，因为那只是参数拼接，和 `this` 无关。

**bind 之后再用 call 改 this 还有效吗？**

无效。`bind` 返回的函数内部已经写死 `apply(context, ...)`，外面再 `call` 传入的新 this 不会影响真正的调用目标。要换 `this` 只能拿原函数重新 `bind`。

### 一句话记住

call 临时挂载调用后删除，bind 闭包预设参数且 new 优先。

## Q11：实现 Koa compose

### 这题在考什么

考你能不能用 **dispatch 递归**实现中间件洋葱模型——每个中间件拿到的 `next` 就是 `dispatch(i + 1)`，`next` 返回 Promise 保证异步顺序，`await next()` 之后的代码在下游执行完才继续，而不是把中间件简单顺序调用。

### 面试时可以这样说

> 洋葱模型的核心是 `dispatch(i)`：它返回调用第 i 个中间件的 Promise，中间件拿到的 `next` 就是 `dispatch(i + 1)`。`await next()` 会等下游整条链执行完再回来，所以 `next` 之前是请求阶段、之后是响应阶段。最后还要防住同一个中间件多次调用 `next`，用一个 index 标记做校验。

**核心一句话**：“dispatch 递归串洋葱，await next 后面的代码在回程执行。”

### 如果对方让你继续讲

完整实现如下：

```js
function compose(middleware) {
  return function (context) {
    let index = -1

    function dispatch(i) {
      // i 没有大于 index，说明同一个 next 被调用了多次
      if (i <= index) {
        return Promise.reject(new Error('next() called multiple times'))
      }
      index = i

      const fn = middleware[i]
      if (!fn) return Promise.resolve()

      try {
        return Promise.resolve(fn(context, dispatch.bind(null, i + 1)))
      } catch (err) {
        return Promise.reject(err)
      }
    }

    return dispatch(0)
  }
}
```

### 对方很可能继续问

**为什么中间件必须在 next 前后写逻辑才构成洋葱？**

`await next()` 是真实的调用边界：之前的代码沿进入方向执行，之后的代码要等整条下游链返回后才继续，正好对应响应回程。如果逻辑全写在 `next` 之前，链就退化成一条直线，没有回程，做不了统计响应耗时、统一包装响应体这类必须在回程执行的事。

**某个中间件不调用 next 会怎样？**

链在这里断掉：后面的中间件不会执行，`await next()` 之后的回程逻辑也不会执行。Koa 里这是合法用法，相当于中间件直接终结响应，比如鉴权失败直接返回 401 就不再往下走。

**compose 里如何防止多次调用 next？**

外层维护一个 `index` 记录最近进入的 dispatch 下标，每次进入 `dispatch` 先比较：同一个中间件第二次调 `next` 时，`i` 不会大于 `index`，命中 `i <= index` 直接 reject 一个错误。不防的话，同一段下游逻辑会被执行两遍，状态可能被重复修改。

### 一句话记住

dispatch 递归串起洋葱，await next 后面的代码在回程执行。

## 面试现场怎么写得更像高级工程师

### 先确认范围

例如手写深拷贝时可以先问：“需要支持 Map、Set、循环引用和属性描述符吗？函数是保持引用还是报错？”先把这些问清楚，不是拖延，而是在定义接口。没有范围就宣称“完整深拷贝”，反而容易被追问击穿。

### 边写边说不变量

并发限制器最重要的不变量是 `activeCount <= limit`，无论任务成功、失败还是同步抛错，都要释放名额。`Promise.all` 最重要的是结果保持输入顺序，而不是完成顺序。先说清这些再落代码，面试官更容易看出你的设计能力。

### 主动补测试

写完至少口述三个测试：空输入、失败路径、边界参数。以防抖为例，还应覆盖组件卸载前取消、连续快速调用以及回调里的 `this`。只跑一个 happy path，代码看起来能用，但不够可靠。

### 被追问“生产环境会这样写吗”

可以坦诚回答：“面试实现展示的是核心机制。生产环境我会优先用经过测试的库或平台原生能力，同时补类型、取消、监控和兼容处理。”这样答，比硬说几十行代码已经生产可用更可信。
