# HTML 与 CSS

## Q1：语义化 HTML 有什么价值？

### 这题在考什么

考你能不能说语义化真正改善的是**可访问性、SEO 和工具对页面的理解**，而不是背标签清单，也别答成“少写 class”或“换用新标签”。

### 面试时可以这样说

> 语义化是用符合内容职责的元素表达结构，例如使用 `button` 表示操作、`nav` 表示导航。它首先改善可访问性和键盘交互，也让搜索引擎、阅读模式和开发工具更容易理解页面。语义化不是为了少写 class，也不是把所有容器都换成新标签；关键是元素行为和内容含义一致。

这段回答的落点在最后一句：把“元素行为和内容含义一致”说清，比罗列标签名更经得起追问。

### 对方很可能继续问

**`button` 和可点击的 `div` 有什么差别？**

`button` 自带键盘操作、焦点语义、禁用状态和辅助技术可识别的角色；`div` 模拟时这些全要手动补，而且很容易漏。默认样式可以完全重置，样式不是拒绝 `button` 的理由。

**ARIA 与原生语义元素怎么选择？**

能用原生元素就不上 ARIA：原生行为免费且跨端一致。ARIA 留给原生表达不了的角色和状态，而且加了 ARIA 还要补齐对应的键盘行为，最终以无障碍树的语义一致为准。

**如何检查键盘可访问性？**

拔掉鼠标，只用键盘走一遍主流程：Tab 顺序是否合理、焦点是否始终可见、Enter/Space 能否触发操作、弹窗会不会困住焦点。Lighthouse 可以辅助，但手测才是主。

### 一句话记住

语义化的核心：元素行为和内容含义一致。

## Q2：CSS 选择器优先级如何计算？

### 这题在考什么

考你能不能说清优先级只是**完整层叠规则中的一环**，而不是只会背四位数字、一遇到覆盖问题就加 `!important`；还要能说清 `:where()`、`:is()`、`:not()` 的优先级从哪来。

### 面试时可以这样说

> 层叠结果先受来源、重要性和层叠层影响，再比较选择器优先级和源码顺序。常规选择器可按 ID、类/属性/伪类、元素/伪元素三个维度比较。内联样式和 `!important` 需要放进完整层叠规则理解，不能只靠一个四位数字。

先说层叠、再说优先级，顺序不要反。这样内联样式和 `!important` 都有地方放，也不会被四位数字带偏。

### 如果对方让你继续讲

工程上我更倾向低优先级、可组合的 class，并通过 CSS Modules、命名约束或 cascade layers 控制边界。

### 这里容易说错

`:where()` 自身优先级为零；`:is()`、`:not()` 的优先级来自参数中最高的选择器。所以不要靠不断追加选择器或 `!important` 去修架构问题。

### 一句话记住

优先级只是完整层叠的一环，`:where()` 为零，`:is()`、`:not()` 看参数里最高的。

## Q3：BFC 是什么，什么时候使用？

### 这题在考什么

考你能不能讲清 BFC 的**隔离机制**和它解决的几类布局问题，而不是只会背“清除浮动”；还要能给出比 `overflow: hidden` 更合适的现代写法。

### 面试时可以这样说

> BFC 是块级元素参与布局时形成的一种独立格式化上下文。它会包含内部浮动，并让内部布局在一定程度上不影响外部，因此常用于清除浮动影响、阻止外边距折叠或创建自适应两栏布局。现代代码中，单纯清除浮动优先使用 `display: flow-root`，布局优先考虑 Flex 或 Grid，不需要为了背 BFC 到处写 `overflow: hidden`。

最后一句主动给出 `flow-root` 和 Flex/Grid 这两个替代方案，能证明你没有停留在背定义。

### 一句话记住

BFC 三个用途：包含浮动、阻止外边距折叠、自适应两栏；实现优先 `display: flow-root`。

## Q4：Flex 和 Grid 如何选？

### 这题在考什么

考你能不能按布局维度说清 Flex 与 Grid 的**选型边界**，而不是把它们当成竞争关系或只背属性列表。

### 面试时可以这样说

> Flex 更适合沿一个主轴分配空间，例如导航、工具栏和卡片内部排列；Grid 更适合同时控制行列的二维布局，例如页面骨架和复杂卡片矩阵。两者不是竞争关系，常见做法是外层 Grid、内部 Flex。所以选型就看一点：布局约束来自内容，还是来自明确的行列结构。

补一句“外层 Grid、内部 Flex”的组合，比单独夸某一种更能体现做过真实布局。

### 对方很可能继续问

**`flex: 1` 实际展开是什么？**

等价于 `flex-grow: 1; flex-shrink: 1; flex-basis: 0%`：先把内容宽度当作 0，再把剩余空间按比例分配。

**为什么 Flex 子项可能无法收缩？**

默认 `min-width: auto`，子项不允许缩到内容最小宽度以下。文本容器通常要加 `min-width: 0`（或 `overflow: hidden`）放开下限，再配合溢出规则。

**Grid 的 `auto-fit` 和 `auto-fill` 有什么差异？**

两者都按容器宽度重复轨道；区别在空轨道的处理：`auto-fill` 保留空轨道占位，`auto-fit` 把空轨道折叠成 0，让已有项目拉伸占满整行。项目少想撑满用 `auto-fit`，想保持固定列宽节奏用 `auto-fill`。

### 一句话记住

一维看 Flex，二维看 Grid；组合时外层 Grid、内部 Flex。

## Q5：CSS Modules、BEM 和 CSS-in-JS 如何选？

### 这题在考什么

考你能不能按项目约束选样式方案，而不是背三种写法的优缺点清单，或宣称哪种写法绝对先进。

### 面试时可以这样说

> 三种方案各管一段：CSS Modules 通过构建阶段生成局部类名，适合已有 CSS 工具链、重视静态样式和低运行时成本的项目；BEM 是纯命名约束，跨技术栈，但依赖团队执行；CSS-in-JS 能让样式与组件状态紧密结合，代价是可能增加运行时、SSR 和调试成本。所以怎么选，不是看哪种写法绝对先进，而是看四个约束：隔离范围、动态样式需求、服务端渲染和团队维护成本。

落点放在“不是哪种写法绝对先进”，再把四个约束套到自己的项目上讲取舍，比继续列优缺点更有说服力。

### 一句话记住

选方案不看先进与否，看隔离、动态、SSR、维护四个约束。

## Q6：Sass 和 PostCSS 有什么区别？

### 这题在考什么

考你能不能说清 Sass 和 PostCSS 在构建链路里**角色不同**，而不是当成二选一的同类工具。

### 面试时可以这样说

> Sass 是带变量、嵌套、mixin 等语法的 CSS 预处理语言，需要编译成 CSS。PostCSS 是用 JavaScript 插件转换 CSS 的处理管线，本身不是一种固定语法；Autoprefixer、现代语法降级和代码检查都可以接入。项目可以同时使用 Sass 和 PostCSS，前者改善作者体验，后者处理产物兼容和工程规则。

把两者说成“一个改善作者体验、一个处理产物”，就不会答成二选一。

### 一句话记住

Sass 管作者体验，PostCSS 管产物处理，两者可以并用。

## Q7：CSS 动画如何保证流畅？

### 这题在考什么

考你知不知道哪些属性的**动画代价低**，而不是凭感觉判断卡不卡；有没有可验证的优化手段和降级意识。

### 面试时可以这样说

> 动画优先只动 `transform` 和 `opacity`，它们不会每帧触发布局和绘制。同时注意别在一屏里动画大量元素和复杂阴影。JavaScript 驱动动画就用 `requestAnimationFrame`，按时间差计算进度。最后还要尊重 `prefers-reduced-motion`，给减少动态效果的用户提供降级。

先给结论“只动 `transform` 和 `opacity`”，再补验证手段和降级，回答就有完整闭环。

### 如果对方让你继续讲

判断动画到底流不流畅，不要凭感觉：用 DevTools 看主线程、帧率和图层。

### 一句话记住

只动 `transform` 和 `opacity`，用 DevTools 验证，并留 `prefers-reduced-motion` 降级。

## Q8：现代 CSS 中哪些能力值得在面试中提？

### 这题在考什么

考你能不能按“解决什么问题”组织答案，而不是罗列 API 名称；有没有补目标浏览器范围和降级策略的意识。

### 面试时可以这样说

回答时按“解决什么问题”来讲，而不是罗列 API：

- 容器查询：组件根据容器而不是视口响应；
- `:has()`：根据后代或相邻状态选择父元素；
- cascade layers：显式管理不同样式来源的层叠顺序；
- 原生嵌套：减少对预处理器的部分依赖；
- 逻辑属性：更好支持不同书写方向；
- `subgrid`：让嵌套网格沿用父级轨道。

回答时再补一句目标浏览器范围，说说降级策略，避免把“浏览器已经支持”说成所有环境都能直接用。

### 一句话记住

按“解决什么问题”讲新特性，末尾补目标浏览器和降级策略。

## 几个高频追问怎么接

### 为什么用 button，不用加了点击事件的 div？

`button` 自带键盘操作、焦点语义、禁用状态和辅助技术可识别的角色。用 `div` 模拟时，这些行为都要自己补，而且很容易漏。所以样式也不是拒绝 `button` 的理由：它的默认样式完全可以重置。

### `flex: 1` 为什么有时把内容撑破？

常见原因不是 flex 失效，而是子项的默认 `min-width: auto` 不允许它缩到内容最小宽度以下。文本容器通常需要 `min-width: 0`，再配合溢出规则。回答这个问题比只背 `flex: 1 1 0%` 更像做过真实布局。

### CSS Modules 能解决所有样式污染吗？

不能。它主要隔离的是类名。全局标签选择器、CSS 变量、字体、动画名称、弹窗挂到 body 之后产生的样式，以及第三方组件的覆盖，这些都还需要治理。组件库还要设计主题 token 和明确的覆盖入口，不能让使用方靠深层选择器硬改内部结构。

### 项目里怎么讲样式方案选型？

可以这样说：“我们的后台项目动态主题有限，但有多人并行开发，所以选了 CSS Modules，靠它保证局部类名，同时用 CSS Variables 管理主题。没选运行时 CSS-in-JS，是因为没有 SSR 需求，动态样式也不复杂，不值得增加运行时和调试成本。”把约束说出来，比列优缺点更有说服力。

## 自测

1. 解释为什么可点击 `div` 不等于 `button`。
2. 不使用四位数字法解释层叠优先级。
3. 为后台系统、组件库分别选择一种样式方案并说明取舍。
4. 在 Flex 与 Grid 之间做一次具体选型。
