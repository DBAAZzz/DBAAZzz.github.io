# 高级前端面试训练

这套文档不是让你从第一页一路读到最后一页。它更像一套面试训练稿：先练第一句话怎么说，再补原理和项目经验，最后让追问把薄弱点暴露出来。

多数题目会按下面的顺序写：

> 先给一段能直接说出口的回答，然后解释为什么；后面再放项目场景、方案取舍和追问参考答案。

不需要逐字背。真正要记的是回答顺序，以及你自己的项目事实。

## 正确使用方式

### 第一轮：只练 30 秒回答

看到题目后先关掉答案，用 30 秒说出：

1. 明确结论；
2. 两到三个关键点；
3. 一个实际影响或使用场景。

如果第一句话还在解释背景，说明答案没有准备好。

例如别人问“什么是闭包”，第一句话应该直接说明函数为什么还能访问外部变量，而不是先从执行上下文、作用域分类和 JavaScript 发展历史讲起。

### 第二轮：练追问

每道题随机选择两个追问，每个追问控制在 60～90 秒。回答时使用：

```text
结论 → 原因 → 项目场景 → 边界或取舍
```

这里也不用机械凑四段。如果问题只是问一个执行结果，先把结果和推导说清楚；如果问题涉及技术选型，再补场景和取舍。

### 第三轮：练项目真实性

项目题必须区分三种口径：

- 我实际负责并落地过；
- 我参与过，但不是主要负责人；
- 当前没有实现，如果重新设计我会这样做。

不要把设计方案说成已经上线的事实。

建议先把文档里的方括号内容换成自己的真实数据。数据暂时找不到时，可以保留“当时没有单独统计”，不要填一个听起来合理的数字。

## 推荐复习顺序

### 只有 7 天

1. JavaScript、浏览器、网络；
2. 性能优化、Webpack/Vite、前端监控；
3. 根据简历重点练两个项目；
4. 系统设计、技术选型、稳定性；
5. 用[七天冲刺计划](./05-模拟面试/02-七天冲刺计划.md)进行两轮模拟。

### 有 2～4 周

先完成核心八股，再按目标岗位选择工程化专题，最后把项目防守和资深开放题混合训练。不要连续几天只阅读，至少一半时间必须开口回答。

## 答案合格标准

一份高级/资深前端答案至少满足下面四项中的三项：

- 有明确结论，不绕圈；
- 能解释机制，而不只是背特点；
- 能说出适用边界和方案取舍；
- 能联系真实项目、指标或故障。

如果答案只有定义和优点列表，它还停留在中级层面。

## 先从哪里开始

第一次使用时，不要同时打开十篇文档。先做下面三件事：

1. 从 JavaScript 核心随机选 5 题，关掉答案录音；
2. 从简历里选最重要的一个项目，填写项目事实表；
3. 用评分表找出最常见的问题，是事实错误、结构混乱，还是追问接不住。

第二天先重答低分题，再增加新内容。这样比连续阅读几个小时有效得多。
